# Minimum amount of R$ 5,00 on a new scheduled charge

**Released:** 2026-09-30 (gateway v0.27.1)

A new scheduled charge must now be at least **R$ 5,00**, the platform minimum per charge. This is the same floor that already applies to the price of a product, an offer and a subscription plan (v0.27.0).

## Minimum amount

| Field | Accepted | Refused with `400` |
|---|---|---|
| Scheduled charge `amount` (`POST /api/v1/scheduled-charges`, `POST /api/scheduled-charges`) | `5.00` and above | below `5.00` |

- It applies to one-time and recurring charges alike, on the dashboard and on the API.
- The message is `O valor mínimo de uma cobrança é R$ 5,00.`.
- `amount` is in **reais** (decimal BRL), never centavos.
- Why: the processor refuses a PIX of R$ 1,50 or less, so a one-time charge at that amount was created but could never be paid.
- Existing scheduled charges are untouched. They keep their amount and keep billing. No route changes the amount of an existing charge: postpone, pause, resume, mark-paid, payment-method changes and charge-now carry no amount.

## Docs

- The scheduled-charge create page and guide state the minimum and show the `400` error.
- They no longer say that the Node SDK attaches `X-Idempotency-Key` automatically. Since `@garuhq/node` 5.0.0 the header is sent only when you pass `idempotencyKey`. The guide also no longer says the API ignores that header on `/scheduled-charges`: the v1 route returns the original series for the same key for 24h.
