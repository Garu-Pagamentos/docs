## Visão Geral

Clona um evento de webhook e dispara a entrega imediatamente. O evento original **não é tocado** — fica no status terminal (`success` ou `failed`) com todo o histórico de tentativas e respostas preservado para auditoria. O clone é uma linha nova na tabela de eventos, carregando `manualResendOf: <uuid_do_original>`.

Disponível a partir da **v0.11.0** (então em `/api/webhook-events`; migrado para `/api/v1/webhook-events` com identificador `uuid`).

<Warning>
  **Mudança de contrato no header `Idempotency-Key`.** Reenvios manuais (este endpoint e o botão "Reenviar" do dashboard) mandam `Idempotency-Key: resend_<uuid>` no POST para o seu endpoint, em vez do `payload.id` original.

  - Handlers que deduplicam pelo valor **bruto** do header já tratam isso como entrega fresca — nenhuma mudança de código. Mas vão começar a receber reenvios manuais que antes eram silenciosamente descartados; idempotência de negócio (orderId, transactionId) precisa absorver.
  - Handlers que deduplicam pelo `payload.id` (idêntico entre original e clone) ou normalizam o header **precisam ser atualizados** — caso contrário, o reenvio é descartado como duplicata.

  Veja o guia [Reenviar webhook](/guias/reenviar-webhook#mudanca-no-idempotency-key) para o código antes/depois.
</Warning>

## `/resend` vs `/retry`

| | `/resend` | `/retry` |
|---|---|---|
| Semântica | **Clona** o evento | **Muta** o evento original |
| Evento original | Intacto, status terminal preservado | Volta para `pending`, contador zerado |
| Histórico de respostas | Mantido no original | **Sobrescrito** pela nova tentativa |
| `Idempotency-Key` outbound | `resend_<uuid_do_clone>` | `event.payload.id` (mesmo do original) |
| Indicado para | Tudo | Legado — preserve apenas se já automatizou em cima dele |

## Exemplo de Requisição

<CodeGroup>

```bash cURL
curl -X POST https://garu.com.br/api/v1/webhook-events/a1b2c3d4-e5f6-7890-abcd-ef1234567890/resend \
  -H "Authorization: Bearer sk_live_sua_chave_api"
```

```javascript JavaScript
import { Garu } from '@garuhq/node';

const garu = new Garu({ apiKey: process.env.GARU_API_KEY });

const clone = await garu.webhookEvents.resend('a1b2c3d4-e5f6-7890-abcd-ef1234567890');
console.log(clone.uuid, clone.manualResendOf); // novo uuid, uuid do original
```

```python Python
import os
import requests

response = requests.post(
    "https://garu.com.br/api/v1/webhook-events/a1b2c3d4-e5f6-7890-abcd-ef1234567890/resend",
    headers={"Authorization": f"Bearer {os.environ['GARU_API_KEY']}"},
)
clone = response.json()
print(clone["uuid"], clone["manualResendOf"])  # novo uuid, uuid do original
```

</CodeGroup>

## Parâmetros de Path

<ParamField path="uuid" type="string" required>
  UUID do evento a clonar e reenviar. Funciona em qualquer status do evento original — `success`, `failed` ou `pending`.
</ParamField>

Sem corpo de requisição.

## Resposta

Retorna o **clone recém-criado** (não o original), em `201 Created`, já em `pending` e com a entrega disparada:


### Campos relevantes

| Campo | Tipo | Descrição |
|---|---|---|
| `uuid` | string | Identificador do **clone** (novo). Use este `uuid` se quiser reenviar de novo. |
| `manualResendOf` | string\|null | `uuid` do evento original. Sempre presente em clones; `null` em eventos originais. |
| `status` | string | Sempre `pending` na criação. Vira `success` ou `failed` conforme a entrega. |
| `payload` | object | Cópia exata do payload do original — `payload.id` (`evt_…`) é preservado. |

<Note>
  O `payload.id` (`evt_…`) do clone é **idêntico** ao do original. Quem muda é o `Idempotency-Key` HTTP outbound: o clone manda `resend_<uuid_do_clone>`, o original mandou `evt_…`.
</Note>

## Rate Limit

**20 requisições por minuto por IP.** Mesmo limite do `/retry`, mesma motivação: cada chamada dispara uma entrega HTTP síncrona para o endpoint do seller.

## Erros

| Status | Caso |
|---|---|
| 404 | Evento não existe ou não pertence ao seller chamando |
| 429 | Rate limit excedido (mais de 20 resends/min do mesmo IP) |

## Onde aparece no dashboard

Toda linha de evento em **Configurações → Webhooks → Eventos** mostra o botão **Reenviar** (visível em `success`, `failed` e `pending`). Reenviar um evento já `success` abre uma confirmação ("este evento já foi entregue com sucesso — reenviar mesmo assim?"). Clones recebem um badge 🔁 na tabela e uma linha **"Reenviado a partir de #&lt;uuid&gt;"** no drawer de detalhes.
